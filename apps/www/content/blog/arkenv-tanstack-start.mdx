TanStack Start reads config in the browser and inside
`createServerFn`. ArkEnv gives those apps one typed `env` object,
checks it before the dev server is ready, and keeps server secrets
inside the server functions.

Public keys such as `VITE_API_URL` belong in the client. `DATABASE_URL`
does not. The same contract you already use on Vite, Next.js, and Nuxt
now has Start wiring.

## Why this matters

One `env.ts` declares both kinds of key. When the Vite plugin is
registered, it validates that file while Vite resolves config. Public
keys are inlined into the client bundle. Server keys become throwing
getters on the client graph, so a component that reads `DATABASE_URL`
throws instead of shipping the secret. `createServerFn` still sees the
real value, because that handler runs on the server.

## What's available

Add ArkEnv from the TanStack CLI, or from `arkenv init` if the app is
already on disk.

- **TanStack CLI add-on.** Scaffold a new app or add the integration
  with `https://arkenv.js.org/tanstack/info.json` (`@tanstack/cli
  create` or `add`).
- **`arkenv init`.** Detects `@tanstack/react-start` or
  `@tanstack/start` and installs `@arkenv/vite-plugin`.
- **`@arkenv/vite-plugin`.** Validates at config resolution, inlines
  public keys, and throws if client code reads a server key.

<Callout type="info" title="On Rsbuild instead?">
  Use `@arkenv/rsbuild-plugin`. The matching example is
  `with-tanstack-start-rsbuild`. The CLI add-on above is the Vite path.
</Callout>

The worked example is
[`examples/with-tanstack-start`](https://github.com/yamcodes/arkenv/tree/v1/examples/with-tanstack-start).

## A taste of the schema

One schema, then a server function that is allowed to read the secret.
The [TanStack Start guide](/docs/frameworks/tanstack-start) has the full
snippets, including Zod and Valibot.

```ts
// src/env.ts
import arkenv from "@arkenv/core";

export const env = arkenv({
  DATABASE_URL: "string",
  VITE_API_URL: "string = 'https://api.example.com'",
});
```

```ts
// inside createServerFn — server-only key is fine
const host = new URL(env.DATABASE_URL).host;
```

The client may read `env.VITE_API_URL`. Reading `env.DATABASE_URL` in
client code throws.
