ArkEnv has officially reached a v1.0 Release Candidate. This is the build we
expect to ship as 1.0, pending your final feedback, docs polish, and a few
last-mile fixes. Now’s the perfect time to kick the tires and help us validate
the final stretch. When 1.0 ships, we’ll update this post (same URL) with any
final notes.

For the RC window, npm `latest` points at the RC builds (`1.0.0-rc.n`, also
under the `rc` tag). The docs apex at [arkenv.js.org](https://arkenv.js.org)
serves v1. v0 docs stay on the archive at
[arkenv-v0.vercel.app](https://arkenv-v0.vercel.app).

## Why this matters

ArkEnv isn’t another thin wrapper around `process.env`. It’s a typesafe
environment variable contract for TypeScript apps: one schema, a validated
`env` object, and fail-fast errors at load — before your app starts serving
traffic with a stringly `PORT` or a truthy `"false"`.

Whether you’re on ArkType, Zod, Valibot, or any
[Standard Schema](https://standardschema.dev/) validator, you keep the tools
you already know. ArkEnv just makes environment variables stop being the
weakest typed surface in the stack.

## What’s in v1

- **One schema → typed `env`.** Declare keys once in `env.ts`. `arkenv()`
  validates at load and TypeScript infers the same types. No loose
  `process.env` helpers, no dual sources of truth.
- **Bring your validator.** ArkType DSL via `@arkenv/core`, or Zod / Valibot /
  Standard Schema via `@arkenv/standard`. Same fail-fast `ArkEnvError` DX
  either way.
- **Full-stack boundary built in.** Next.js, Nuxt, Vite, Bun, and TanStack
  Start integrations keep server secrets off the client while public keys stay
  typed.
- **A real CLI.** `arkenv` on npm is the CLI (`init`, `check`) — not the
  runtime. Scaffold and validate without treating the installer as a library.
- **Canonical `./env` everywhere.** Framework plugins rewrite imports of your
  env module. They no longer take a schema in the plugin call.

## If you’re on v0

The headline change is package identity:

- **`arkenv` is the CLI.** Importing it as a library throws on purpose, so a
  half-migrated app fails loudly instead of silently shipping the wrong thing.
- **Runtime lives in `@arkenv/core`** (ArkType) or **`@arkenv/standard`**
  (Zod / Valibot / Standard Schema).
- **Vite and Bun plugins are transform-only.** Export `env` from a canonical
  `./env` module; don’t pass a schema into the plugin.

Keep `import { env } from "./env"` in application code. Point the schema
module at the new packages. Update framework wiring per the migrate guide.

## Path to 1.0 stable

We plan to cut 1.0 shortly after collecting RC feedback. Expect a few small RC
iterations; any breaking changes will be clearly documented. As we approach
stable, only light polish remains. No major API shifts.
