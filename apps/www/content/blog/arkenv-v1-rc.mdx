## What’s happening

- ArkEnv **v1** is out as a **Release Candidate** (`1.0.0-rc.n`)
- npm **`latest`** points at RC for the RC window (also published under the **`rc`** tag)
- Docs apex (`https://arkenv.js.org`) serves **v1 / RC**
- v0 docs stay available on the archive: [https://arkenv-v0.vercel.app](https://arkenv-v0.vercel.app)

## Notable for newcomers

- **One schema → typed `env`:** declare keys once in `env.ts`; `arkenv()` validates at load and TypeScript infers the same types — no loose `process.env` / stringly helpers
- **Bring your validator:** ArkType DSL via `@arkenv/core`, or Zod / Valibot / any [Standard Schema](https://standardschema.dev/) via `@arkenv/standard` — same fail-fast `ArkEnvError` DX either way
- **Full-stack boundary built in:** Next.js, Nuxt, Vite, Bun (and related) integrations keep server secrets off the client while public keys stay typed

## If you’re on v0

- `arkenv` on npm is now the **CLI**, not the runtime — importing it as a library throws
- Runtime lives in **`@arkenv/core`** (ArkType) or **`@arkenv/standard`** (Zod / Valibot / Standard Schema)
- Vite / Bun plugins no longer take a schema in the plugin call — use a canonical `./env` module

## How to migrate

- Read: [Migrating to v1](/docs/guides/migrating-to-v1) ([live](https://arkenv.js.org/docs/guides/migrating-to-v1))
- Swap packages: remove v0 `arkenv` / `@arkenv/cli` → install `@arkenv/core` (+ `arktype`) or `@arkenv/standard`, plus `arkenv` as a **devDependency** (CLI)
- Point imports at the new packages; keep `import { env } from "./env"`
- Update Vite / Bun / Next / Nuxt wiring per the guide (transform-only plugins, no schema-in-plugin)
