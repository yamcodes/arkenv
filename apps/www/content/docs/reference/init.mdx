`arkenv` on npm is the CLI. It scaffolds schemas and wires framework
config. Validation lives in `@arkenv/core` or `@arkenv/standard`.

```package-install
npx arkenv@latest init
```

```package-install
npx arkenv@latest init my-app --example with-vite-react -H vercel
```

```package-install
npx arkenv@latest init --agent --flat
```

Install locally when you want a project binary:

```package-install
npm install -D arkenv
```

## Usage

```txt title="Terminal"
arkenv init [project-name] [options]
```

Omit `project-name` to mutate the current directory. Pass a name to
create a new folder (optionally from `--example`).

[Global flags](/docs/reference#global-flags) (`--yes`, `--quiet`,
`--json`, `--agent`, `--help`) apply here too.

## Options

These flags are specific to `init`.

### `--force` / `-f`

Bypass dirty-git and other safety checks, then force scaffolding. The
CLI refuses a dirty working tree unless you pass this flag. Commit or
stash first if you don't want to overwrite generated files.

### `--flat`

Scaffold a single `env.ts`. This is the default layout.

### `--strict`

Scaffold `env/client.ts`, `env/server.ts`, and
`env/internal/shared.ts`.

### `--no-codegen`

Skip Next.js `env.gen.ts` generation and related `withArkEnv` wiring.

### `--preset` / `-P`

Pre-populate provider system variables. Values: `none`, `vercel`,
`netlify`, `cloudflare`, `railway`, `render`, `fly`. The CLI also accepts
`--host-preset` and `-H` as aliases.

See [Hosting presets](/docs/validating-your-environment/hosting-presets).
To apply or remove presets later, use [`preset`](/docs/reference/preset).

### `--agent`

Same macro as the [global `--agent` flag](/docs/reference#agent):
`--yes --quiet --json`. It does not imply `--force`.

When a safety check fails (dirty git tree), stdout is a JSON refusal and
the process exits non-zero:

```json
{
  "status": "error",
  "code": "GIT_TREE_DIRTY",
  "message": "Git working tree is not clean.",
  "retryWith": ["--force"]
}
```

Only rerun with flags in `retryWith` after you confirm the bypass is
safe.

### `--example <name>`

Scaffold from a named example when creating a new project. Short `-e` is
reserved and rejected.

See [Start with an example](/docs/getting-started/examples).

<Callout type="warn">
  `--simple` is deprecated and no longer supported. The CLI errors if you
  pass it. Use `--flat` (the default) instead.
</Callout>

## Output

Depending on the detected framework and flags, `init` writes:

- Schema file(s): `env.ts` or the strict `env/` tree (often under
  `src/`)
- `.env` / `.env.example` when missing. Init never reads an existing
  `.env`; a missing `.env.example` is filled from detected keys and
  defaults, then `sync` refreshes `.env.example` from the loaded
  schema in an existing project. If `.env` is missing, init may copy
  `.env.example` into it.
- Next.js: `withArkEnv` in `next.config.*`, optional
  `generated/env.gen.ts`
- Vite / Bun: type augmentation files (`vite-env.d.ts`, `bun-env.d.ts`)
- Dependency installs for the chosen dialect (`@arkenv/core`, plugins,
  Zod/Valibot)

## Import the validator from core

The CLI package is not the validation library. Import `arkenv()` from
`@arkenv/core` (or `@arkenv/standard`).

```ts
// Wrong: arkenv is the CLI package
import arkenv from "arkenv";

// Right
import arkenv from "@arkenv/core";
```

Importing `arkenv` as a library throws and points you at `@arkenv/core`.
