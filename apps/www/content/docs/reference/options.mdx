The second argument to `arkenv()` is an optional configuration object. Shared fields (`env`, `coerce`, `safe`, `emptyAsUndefined`, `onUndeclaredKey`, …) exist on both engines. `toJsonSchema` exists only on [`@arkenv/standard`](/docs/reference/standard): ArkType already exposes JSON Schema, so [`@arkenv/core`](/docs/reference/core) has nothing to fall back to.

## Configuration options

<AutoTypeTable path="../../packages/core/src/arkenv.ts" name="ArkEnvConfig" expandAll />

`ArkEnvConfig` is the ArkType engine table. `StandardEnvConfig` is that table plus optional `toJsonSchema`. See [toJsonSchema](#tojsonschema-standard-mode-only).

## Examples

### Custom env source

Pass a record instead of `process.env` in tests, Cloudflare Workers, or when using Vite `loadEnv`:

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv(
  { PORT: "number.port" },
  { env: { PORT: "3000" } },
);
```

### Disabling coercion

Coercion is on by default. Turn it off when you want raw strings and morph them yourself:

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv(
  { PORT: "string" },
  { coerce: false, env: { PORT: "3000" } },
);

env.PORT; // "3000"
```

See [Coercion and parsing](/docs/validating-environment-variables/coercion-and-parsing).

### JSON arrays

Comma-separated arrays are the default. Use JSON when your host stores array env as JSON strings:

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv(
  { TAGS: "string[]" },
  { arrayFormat: "json", env: { TAGS: '["web", "app"]' } },
);
```

### Empty strings as missing

With `PORT=` in a `.env` file, `emptyAsUndefined` treats the value as absent so schema defaults apply:

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv(
  {
    PORT: "number.port = 3000",
    DEBUG: "boolean = false",
  },
  {
    emptyAsUndefined: true,
    env: {
      PORT: "",
      DEBUG: "",
    },
  },
);

env.PORT; // 3000
env.DEBUG; // false
```

### `toJsonSchema` (standard mode only)

Pass a fallback converter for Standard Schema validators that omit JSON Schema on the value (notably Valibot). ArkEnv calls it per key when it can't read JSON Schema from that value. Wiring: [Valibot](/docs/guides/validators/valibot) and [Coercion](/docs/core-concepts/coercion#valibot-tojsonschema).

This field is not on ArkType `ArkEnvConfig`. Vite/Bun `/standard` plugin configs that alias `ParseStandardConfig` inherit it.

### Rejecting undeclared keys

ArkEnv defaults to `"delete"`: undeclared keys may appear on input and are stripped from the output. Fail instead when you want a strict inventory:

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv(
  { PORT: "number.port" },
  {
    onUndeclaredKey: "reject",
    env: { PORT: "3000", EXTRA: "nope" },
  },
);
```

### Safe results instead of throws

Return `{ success, data | issues }` when you handle failures yourself (tests, custom boot UI):

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

const result = arkenv(
  { PORT: "number.port" },
  { safe: true, env: { PORT: "invalid" } },
);

if (!result.success) {
  console.error(result.issues);
} else {
  console.log(result.data.PORT);
}
```

<Callout type="warn">
  Framework plugins omit `safe` so a failed validation cannot soft-fail into the
  client bundle. Call `arkenv()` yourself if you need programmatic failure
  handling outside a plugin.
</Callout>

## Framework-only options

Next.js and Nuxt wrappers accept `extends` to merge shared or client env objects into a server schema. That field lives outside core `ArkEnvConfig`. See [Client vs. server](/docs/validating-environment-variables/client-vs-server).
