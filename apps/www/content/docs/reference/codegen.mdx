title: codegen
description: Next.js env.gen.ts generation via withArkEnv.
---

There is no `arkenv codegen` CLI command. Codegen is a **Next.js** feature provided by [`@arkenv/nextjs/config`](/docs/reference/nextjs).

Vite and Bun keep `env.ts` as the surface and do not emit `env.gen.ts`.

## `withArkEnv`

Wrap your Next.js config so ArkEnv can generate a typed factory and enforce the client boundary:

```ts title="./next.config.ts"
import type { NextConfig } from "next";
import { withArkEnv } from "@arkenv/nextjs/config";

const nextConfig: NextConfig = {};

export default withArkEnv(nextConfig);
```

By default this writes `generated/env.gen.ts` (path configurable). Your app schema imports the generated factory:

```ts title="./env.ts"
import arkenv from "@/generated/env.gen";

export const env = arkenv({
	DATABASE_URL: "string",
	NEXT_PUBLIC_API_URL: "string",
});
```

## Config options

| Option       | Default  | Meaning                                           |
| ------------ | -------- | ------------------------------------------------- |
| `codegen`    | `true`   | Write `env.gen.ts`                                |
| `validate`   | `true`   | Validate the schema during config/build           |
| `schemaPath` | auto     | Path to your schema entry                         |
| `outputPath` | auto     | Path for the generated file                       |
| `layout`     | `"flat"` | `"flat"` or `"strict"` (`"simple"` is deprecated) |
| `standard`   | `false`  | Generate for `@arkenv/standard` schemas           |

Skip generation during CLI scaffolds with `arkenv init --no-codegen`.

## Programmatic API

```ts
import { runCodegen } from "@arkenv/nextjs/config";

await runCodegen(schemaPath, outputPath);
```

Use this from custom tooling. Day-to-day apps should rely on `withArkEnv`.

## Standard Schema codegen

```ts title="./next.config.ts"
import { withArkEnv } from "@arkenv/nextjs/standard/config";

export default withArkEnv(nextConfig);
```

Forces Standard Schema-compatible generated imports.
