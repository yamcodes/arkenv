`@arkenv/bun-plugin` validates environment variables for Bun builds and
fullstack apps that inline client env. Backend-only Bun scripts use
[`@arkenv/core`](/docs/reference/core).

## Installation

```package-install
npm install -D @arkenv/bun-plugin
npm install @arkenv/core arktype
```

Or if you use Zod, Valibot, or another Standard Schema validator:

```package-install
npm install -D @arkenv/bun-plugin
npm install @arkenv/standard
```

## Exports

The default export is a hybrid `arkenvPlugin` instance. Named exports
are explicit aliases.

| Export                  | Role                                     |
| ----------------------- | ---------------------------------------- |
| default                 | `arkenvPlugin` hybrid plugin instance    |
| named `arkenvPlugin`    | Hybrid plugin factory and instance       |
| named `arkenvBunPlugin` | Host-explicit named alias                |
| named `hybrid`          | Explicit zero-config hybrid plugin alias |
| `./standard`            | Standard Schema plugin entry             |

`arkenvPlugin` is both a factory (`arkenvPlugin({ schemaPath })`) and a
`BunPlugin` object with `name`, `target`, and `setup`. You can:

- Preload in `bunfig.toml`: `plugins = ["@arkenv/bun-plugin"]`
- Register in `Bun.build`: `plugins: [arkenvPlugin]`
- Pass transform options:
  `plugins: [arkenvPlugin({ schemaPath: "./src/env.ts" })]`

`arkenvBunPlugin` is the host-explicit alias for monorepos that load
more than one bundler plugin.

Default client prefix: `BUN_PUBLIC_`.

## Usage

Register the plugin in `Bun.build` (or your fullstack server setup).

```ts title="./build.ts"
import arkenvPlugin from "@arkenv/bun-plugin";

await Bun.build({
  entrypoints: ["./src/index.ts"],
  plugins: [arkenvPlugin()],
});
```

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv({
  DATABASE_URL: "string",
  BUN_PUBLIC_API_URL: "string",
});
```

## Transform options

Same transform call shape as
[`@arkenv/vite-plugin`](/docs/reference/vite-plugin):

- `arkenvPlugin()` or
  `arkenvPlugin({ schemaPath, clientPrefix, ... })` rewrites the schema
  module in the client graph.
- A schema argument is rejected. Define the schema in `env.ts` and
  import `{ env }` from there.

Plugin config omits `safe` so failed validation cannot soft-fail into
the bundle.

## Types

Import the validated `env` object from your schema module.

:::warning[Do not read `process.env` directly]
Reading `process.env` skips ArkEnv. Import `{ env }` so public keys stay
typed and coerced and server secrets stay out of the client bundle.
:::
