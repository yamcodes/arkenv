title: validate
description: How ArkEnv validates environment variables at runtime and in builds.
---

There is no `arkenv validate` CLI command. Validation runs when you call `arkenv()` and when framework plugins run during build or boot.

## Runtime validation

Importing your env module parses the configured source immediately:

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv({
	DATABASE_URL: "string",
	PORT: "number.port = 3000",
});
```

Invalid or missing values throw [`ArkEnvError`](/docs/validating-environment-variables/error-reporting). Use `{ safe: true }` only when you handle the result yourself (tests, custom boot UI).

## Framework build validation

| Integration | How validation runs |
| --- | --- |
| Next.js | [`withArkEnv`](/docs/reference/nextjs) runs schema validation during config/build (`validate` defaults to `true`) |
| Nuxt | [`@arkenv/nuxt/module`](/docs/reference/nuxt) validates via `arkenv.validate` (default `true`) |
| Vite | [`@arkenv/vite-plugin`](/docs/reference/vite-plugin) validates in dev and build |
| Bun | [`@arkenv/bun-plugin`](/docs/reference/bun-plugin) validates during Bun bundler builds |

Disable framework validation only when you have a deliberate reason (for example a docs site that must build without secrets). Prefer failing the build over shipping with unchecked config.

## Checking env in CI

Run the same entrypoint your app uses:

```bash title="Terminal"
# Example: load .env then execute a file that imports ./env
node --import tsx -e 'import "./env.ts"'
```

Or assert in tests by calling `arkenv(schema, { env: fixture, safe: true })`.
