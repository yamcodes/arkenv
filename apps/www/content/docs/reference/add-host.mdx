The ArkEnv CLI injects provider system environment variables into a
schema you already have. Use it when you change hosts or finish a schema
that started without a preset.

```package-install
npx arkenv@latest add host vercel
```

```package-install
npx arkenv@latest add host
```

## Usage

```txt title="Terminal"
arkenv add host [provider] [options]
```

`provider` is optional. Omit it to pick interactively.

Accepted providers: `vercel`, `netlify`, `cloudflare`, `railway`,
`render`, `fly`.

[Global flags](/docs/reference#global-flags) apply. With `--yes` and no
provider, the command uses `vercel`.

## Behavior

The command detects layout (flat `env.ts` vs strict `env/client.ts` +
`env/server.ts`), framework prefix (`NEXT_PUBLIC_`, `NUXT_PUBLIC_`,
`VITE_`), and validator dialect (ArkType, Zod, Valibot). Then the CLI:

1. Partitions preset keys into server-only and client-exposed groups
2. Writes those groups into the matching schema files, leaving existing
   keys unchanged

If the schema file is missing or unparseable, the CLI prints the
proposed fields for you to paste.

## Provider fields

Every preset field is optional (present only on that host). See
[Hosting presets](/docs/validating-your-environment/hosting-presets) for
the full key tables.

| Provider   | Server-only examples              | Client-exposed examples           |
| ---------- | --------------------------------- | --------------------------------- |
| Vercel     | `VERCEL`                          | `VERCEL_ENV`, `VERCEL_URL`        |
| Netlify    | `NETLIFY`, `DEPLOY_URL`           | `CONTEXT`, `URL`                  |
| Cloudflare | `CF_PAGES`, `CF_PAGES_COMMIT_SHA` | `CF_PAGES_BRANCH`, `CF_PAGES_URL` |
| Railway    | `RAILWAY_*`                       | (none)                            |
| Render     | `RENDER*`                         | (none)                            |
| Fly.io     | `FLY_*`                           | (none)                            |
