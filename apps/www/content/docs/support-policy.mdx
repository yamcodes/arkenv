v1 is published as `1.0.0-alpha.x` under the `alpha` npm tag. **APIs can
still change before 1.0.0.** Use the latest version whenever you can.

## Package managers

The [`arkenv` CLI](/docs/reference/init) detects the package manager in
your repository. Published packages are plain npm packages.

| Package manager | Support |
| --------------- | ------- |
| pnpm            | Alpha   |
| npm             | Alpha   |
| yarn            | Alpha   |
| bun             | Alpha   |

## Frameworks

| Framework   | Support |
| ----------- | ------- |
| Next.js 13.4+ | Alpha via [`@arkenv/nextjs`](/docs/reference/nextjs) |
| Nuxt 3+     | Alpha via [`@arkenv/nuxt`](/docs/reference/nuxt) |
| Vite 4+     | Alpha via [`@arkenv/vite-plugin`](/docs/reference/vite-plugin) |
| Bun 1.0+    | Alpha via [`@arkenv/bun-plugin`](/docs/reference/bun-plugin) |

Vite-based apps (e.g. SolidStart) use `@arkenv/vite-plugin`. Apps that only use Bun as a package manager or runtime (but not a Bundler or fullstack dev server) should stay on
[`@arkenv/core`](/docs/reference/core) or
[`@arkenv/standard`](/docs/reference/standard).

<Callout type="info">
  Frameworks have their own release schedules. New major versions are not always supported on day one.
</Callout>

## Node.js

ArkEnv intends to support the
[Active and Maintenance LTS versions of Node.js](https://nodejs.org/en/about/previous-releases).
The [CLI](/docs/reference/init), plugins, and
[examples](/docs/getting-started/examples) depend on that. CI runs on
`lts/*` and `latest`.

## Deprecated

These APIs still work on [`@arkenv/nextjs`](/docs/reference/nextjs) and
[`@arkenv/nuxt`](/docs/reference/nuxt). They will be removed in a later
release.

- Nested `arkenv({ server, client, shared, runtimeEnv })`. Use
  `arkenv(schema, options)` instead. The `runtimeEnv` option on that
  second argument is current, not deprecated.
- Options `expose` and `shared`. Use `exposeToClient`. See
  [Client vs. server](/docs/validating-environment-variables/client-vs-server).
- Config `layout: "simple"`. Use `"flat"`.

Importing the `arkenv` package as a library already throws. Use
[`@arkenv/core`](/docs/reference/core) or
[`@arkenv/standard`](/docs/reference/standard). `arkenv init --simple`
is already rejected.

The [changelog](https://github.com/yamcodes/arkenv/releases) lists what
changed in each release.
