`@arkenv/nextjs` validates Next.js environment variables, generates
typesafe accessors, and blocks server secrets from Client Components.

For high-level architectural trade-offs, see
[Frameworks](/docs/frameworks).

## Quickstart

Scaffold Next.js integration in an existing project using the CLI:

```package-install
npx arkenv init
```

The CLI detects Next.js, installs the required packages, wraps `next.config`
with `withArkEnv`, gitignores `.arkenv/`, and creates your initial schema
file importing from `@/.arkenv`.

## Manual installation

If you prefer manual setup, install `@arkenv/nextjs` alongside your chosen
validation engine.

### ArkType engine

Install `@arkenv/core` and its peer dependency `arktype`:

```package-install
npm install @arkenv/core @arkenv/nextjs arktype
```

### Standard Schema engine

If you aren't using ArkType, install `@arkenv/standard` with Zod or
Valibot:

```package-install
npm install @arkenv/standard @arkenv/nextjs zod
```

```package-install
npm install @arkenv/standard @arkenv/nextjs valibot @valibot/to-json-schema
```

## Configuration

Wrap your Next.js configuration object with `withArkEnv`. This plugin runs schema
validation during development and builds, and generates typed accessors in
`.arkenv/env.gen.ts`. Import that factory as `@/.arkenv`. Add `.arkenv/`
to `.gitignore`.

```ts title="./next.config.ts" twoslash
import type { NextConfig } from "next";
import { withArkEnv } from "@arkenv/nextjs/config";

const nextConfig: NextConfig = {};

export default withArkEnv(nextConfig);
```

Function-form configs work too. `withArkEnv` awaits your factory, then applies
aliases to the resolved object (including phase-dependent options):

```ts title="./next.config.ts"
import type { NextConfig } from "next";
import { withArkEnv } from "@arkenv/nextjs/config";

export default withArkEnv(async (phase, { defaultConfig }): Promise<NextConfig> => ({
  ...defaultConfig,
  reactStrictMode: phase !== "phase-test",
}));
```

## Schema

Use a single `env.ts`. Client variables must use the `NEXT_PUBLIC_` prefix.
Zod and Valibot use the same `@/.arkenv` factory; point `withArkEnv` at
`@arkenv/nextjs/standard/config` (shown below).

<Tabs items={["ArkType", "Zod", "Valibot"]}>
  <Tab value="ArkType">
    ```ts title="./env.ts" twoslash
    import arkenv from "@/.arkenv";

    export const env = arkenv({
    	DATABASE_URL: "string",
    	NEXT_PUBLIC_API_URL: "string = 'https://api.example.com'",
    	NODE_ENV: "'development' | 'production' | 'test' = 'development'",
    });
    ```
  </Tab>

  <Tab value="Zod">
    ```ts title="./env.ts" twoslash
    import arkenv from "@/.arkenv";
    import * as z from "zod";

    export const env = arkenv({
    	DATABASE_URL: z.url(),
    	NEXT_PUBLIC_API_URL: z.url().default("https://api.example.com"),
    	NODE_ENV: z
    		.enum(["development", "production", "test"])
    		.default("development"),
    });
    ```
  </Tab>

  <Tab value="Valibot">
    ```ts title="./env.ts" twoslash
    import arkenv from "@/.arkenv";
    import * as v from "valibot";

    export const env = arkenv({
    	DATABASE_URL: v.pipe(v.string(), v.url()),
    	NEXT_PUBLIC_API_URL: v.optional(
    		v.pipe(v.string(), v.url()),
    		"https://api.example.com",
    	),
    	NODE_ENV: v.optional(
    		v.picklist(["development", "production", "test"]),
    		"development",
    	),
    });
    ```
  </Tab>
</Tabs>

Import `env` anywhere in your application. When client code accesses a server key
such as `DATABASE_URL`, ArkEnv throws a runtime error to prevent data leaks.

If secret **names or types** must stay out of the client type graph as well as
values, use the optional [two-module recipe](/docs/core-concepts/client-vs-server#advanced-two-module-recipe).

## Standard Schema

Zod and Valibot both import `withArkEnv` from
`@arkenv/nextjs/standard/config`. The schema itself stays on
`@/.arkenv`, as in the tabs above.

`@arkenv/nextjs/standard` binds the root `@arkenv/standard` engine.
Zod 4.2+ coerces numbers and booleans from that entry. Valibot does
not: there is no `@arkenv/nextjs/standard/valibot` binding, so
installing `@valibot/to-json-schema` does not turn `v.number()` or
`v.boolean()` into coerced fields here. Keep Valibot fields as strings
on this entry, or validate them with
[`@arkenv/standard/valibot`](/docs/validators/valibot) outside the
Next.js factory.

```ts title="./next.config.ts" twoslash
import type { NextConfig } from "next";
import { withArkEnv } from "@arkenv/nextjs/standard/config";

const nextConfig: NextConfig = {};

export default withArkEnv(nextConfig);
```

## Read `env` in application code

Import `{ env } from "./env"` in Server Components, route handlers, and
Client Components.

:::warning[Do not read `process.env` directly]
Reading `process.env` skips ArkEnv. Import `{ env }` so public keys stay
typed and coerced and server secrets stay out of the client bundle.
:::

```ts title="./app/page.tsx"
import { env } from "../env";

export default function Page() {
  return <p>{env.NEXT_PUBLIC_API_URL}</p>;
}
```

Reading `env.DATABASE_URL` from a Client Component throws. See
[Client vs. server](/docs/core-concepts/client-vs-server).
