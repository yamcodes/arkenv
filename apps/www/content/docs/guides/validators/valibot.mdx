Valibot via [`@arkenv/standard`](/docs/reference/standard). Engine choice: [Choosing an engine](/docs/core-concepts/standard-schema).

Valibot implements Standard Schema validation. JSON Schema conversion lives in [`@valibot/to-json-schema`](https://valibot.dev/guides/json-schema/), not on each schema value. Pass ArkEnv's optional `toJsonSchema` callback once so `v.number()` and `v.boolean()` pre-coerce the way Zod fields do.

## Install

```package-install
pnpm add @arkenv/standard valibot @valibot/to-json-schema
```

## Minimal `env.ts`

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/standard";
import * as v from "valibot";
import { toJsonSchema } from "@valibot/to-json-schema";

export const env = arkenv(
  {
    DATABASE_URL: v.pipe(v.string(), v.url()),
    PORT: v.optional(v.number(), 3000),
    DEBUG: v.optional(v.boolean(), false),
    NODE_ENV: v.optional(
      v.picklist(["development", "production", "test"]),
      "development",
    ),
  },
  {
    toJsonSchema: (schema) =>
      toJsonSchema(schema as v.GenericSchema, {
        typeMode: "input",
        target: "draft-07",
      }),
  },
);
```

Use `v.number()` / `v.boolean()` with this callback. Skip `v.transform(Number)` for env strings.

## Coercion (`toJsonSchema`)

Pass an explicit wrapper. A bare `{ toJsonSchema }` function reference uses Valibot's default `typeMode: "ignore"`, which mis-coerces piped schemas.

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/standard";
import * as v from "valibot";
import { toJsonSchema } from "@valibot/to-json-schema";

export const env = arkenv(
  { PORT: v.number(), DEBUG: v.boolean() },
  {
    toJsonSchema: (schema) =>
      toJsonSchema(schema as v.GenericSchema, {
        typeMode: "input",
        target: "draft-07",
      }),
  },
);
```

- `target: "draft-07"` matches the JSON Schema draft ArkEnv expects.
- `typeMode: "input"` coerces env strings toward the schema's input type.
- Valibot's converter does not accept Standard Schema, so assert `as v.GenericSchema` at the call. Same wrapper for Valibot-only and Zod + Valibot (classic Zod never reaches the callback at runtime).
- Return `undefined` to skip one key. A throw or non-plain object fails the parse with `ArkEnvError` for that key.

Configure `toJsonSchema` once on `arkenv()`. Per-key `toStandardJsonSchema(...)` wrappers are not the intended path.

When a second library also omits JSON Schema on the value, switch on `schema["~standard"].vendor`. Zod Mini is that second case (`z.toJSONSchema`, vendor `"zod"`). Assert at each host-converter call — `vendor` does not narrow Mini vs Valibot. Example: [Mixing with Zod Mini](/docs/core-concepts/coercion#mixing-with-zod-mini).

## Defaults and optionals

| Pattern                   | Meaning                         |
| ------------------------- | ------------------------------- |
| `v.optional(schema, def)` | Default when the key is missing |
| `v.optional(schema)`      | Optional key                    |
| `emptyAsUndefined: true`  | Treat empty strings as missing  |

## Frameworks

Use each host's `/standard` entry and pass the same `toJsonSchema` option (plugin configs alias `ParseStandardConfig` / `StandardEnvConfig`):

- [Next.js](/docs/guides/frameworks/nextjs) (`@arkenv/nextjs/standard`)
- [Nuxt](/docs/guides/frameworks/nuxt)
- [Vite](/docs/guides/frameworks/vite) (`@arkenv/vite-plugin/standard`)
- [Bun](/docs/guides/frameworks/bun) (`@arkenv/bun-plugin/standard`)
