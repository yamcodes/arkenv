ArkEnv is designed to work seamlessly with AI coding assistants like Claude Code,
Cursor, and GitHub Copilot. ArkEnv provides capabilities that help assistants
understand your environment schemas, scaffold configurations deterministically,
and enforce client/server security boundaries.

## Agent skill

[Agent Skills](https://agentskills.io) are an open standard that provide capabilities
and domain expertise to AI coding assistants.

You can install the official ArkEnv skill into your project using your package
manager:

```package-install
npx skills add yamcodes/arkenv
```

The skill teaches assistants:

- Schema authoring for both ArkType (`@arkenv/core`) and Standard Schema (`@arkenv/standard` with Zod or Valibot)
- Client and server boundary rules and framework public prefixes (`NEXT_PUBLIC_`, `NUXT_PUBLIC_`, `VITE_`, `BUN_PUBLIC_`)
- Non-interactive scaffolding using the [`--agent`](/docs/reference/init#agent) CLI flag to conserve context window tokens
- Keeping `.env.example` templates synchronized without leaking secret values

Learn more about discovering and managing skills at [skills.sh](https://skills.sh).

## Prompts that work well

Copy these prompts into your assistant for consistent results:

**Greenfield setup**

```text
Add ArkEnv to this repo. Run `npx arkenv@latest init --agent`, parse the JSON on stdout, and only retry with flags from `retryWith` if a refusal is safe to bypass. Do not hand-write next.config or env.ts unless init fails.
```

**Existing keys**

```text
We already have a .env.example. Run `npx arkenv@latest init --agent` and accept the detected keys for the schema. Keep .env.example values empty or placeholder-only; never copy secrets from .env into git.
```

**Migrate raw process.env usage**

```text
Find direct `process.env` and `import.meta.env` reads and route them through the typed `env` export from env.ts (or strict env/client.ts and env/server.ts). Do not add a runtimeEnv map. Match the framework public prefix (NEXT_PUBLIC_, NUXT_PUBLIC_, VITE_, BUN_PUBLIC_).
```

**Add a variable**

```text
Add DATABASE_URL to the ArkEnv schema with the right type, update .env.example with an empty value, and document the key in a comment if it is non-obvious. Do not expose server keys on the client.
```

**Hosting preset**

```text
Add the Vercel hosting preset with `npx arkenv@latest add host vercel --agent` and merge any new system vars into the schema.
```

## Machine-readable documentation

ArkEnv's documentation site is optimized for AI consumption in several ways:

### Direct markdown routes

Append `.md` or `.mdx` to any documentation URL (or fetch via `/llms.mdx/docs/...`) to get a raw Markdown version, avoiding HTML markup and saving context tokens:

- `/docs/guides/frameworks/nextjs.md`
- `/docs/validating-your-environment/client-vs-server.md`
- `/llms.mdx/docs/guides/frameworks/nextjs`

### Curated index (`/llms.txt`)

A concise index of all documentation sections is available at [/llms.txt](/llms.txt) for lightweight discovery.

### Full documentation (`/llms-full.txt`)

The complete text of all documentation pages is available in a single plain text file at [/llms-full.txt](/llms-full.txt).
