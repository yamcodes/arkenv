To get the best experience with `arkenv`, ArkEnv provides a few utilities for integrating with your editor.

## Syntax highlighting and inline type errors

:::note
Skip this if you're using ArkEnv without ArkType (i.e. [`@arkenv/standard`](/docs/reference/standard)).
:::

Enable syntax highlighting and inline type errors with the 
[VS Code extension](https://marketplace.visualstudio.com/items?itemName=arktypeio.arkdark) or [JetBrains plugin](https://plugins.jetbrains.com/plugin/27099-arktype).

If you use this extension, it is **not** recommended to use an alias like
`createEnv`. It only works if the function contains the substring `ark`.

```diff title="./env.ts"
- import createEnv from "@arkenv/core";
+ import arkenv from "@arkenv/core";

- export const env = createEnv({
+ export const env = arkenv({
    PORT: "number.port = 3000",
    DEBUG: "boolean = false",
  });
```

## ArkThemes

:::note
Skip this if you're using ArkEnv without ArkType (i.e. [`@arkenv/standard`](/docs/reference/standard)).
:::

This theme for VS Code (or Cursor) is recommended to provide advanced syntax highlighting and colors that work well with ArkType since they make its [DSL](https://en.wikipedia.org/wiki/Domain-specific_language) look like plain TypeScript. Available in light and dark modes.

Visit the [VSCode Extension Marketplace](https://marketplace.visualstudio.com/items?itemName=arktypeio.arkthemes) to install.

## Autocomplete on `env.*`

TypeScript reads keys and types from the schema you pass to `arkenv()`:

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv({
  HOST: "string.host = 'localhost'",
  PORT: "number.port = 3000",
  NODE_ENV: "'development' | 'production' | 'test' = 'development'",
});
```

Import `{ env }` in application code. `env.PORT` is a `number`;
`process.env.PORT` stays an untyped string.

## Framework type augmentation

Some hosts expose env through globals. The ArkEnv CLI can scaffold these
declaration files.

### Vite: `vite-env.d.ts`

```ts title="./vite-env.d.ts"
/// <reference types="vite/client" />

type ImportMetaEnvAugmented =
  import("@arkenv/vite-plugin").ImportMetaEnvAugmented<
    typeof import("./env").Env
  >;

interface ImportMetaEnv extends ImportMetaEnvAugmented {}
```

`import.meta.env.VITE_*` keys autocomplete in client code. Keys without
the `VITE_` prefix error there.

### Bun fullstack: `bun-env.d.ts`

```ts title="./bun-env.d.ts"
/// <reference types="bun-types" />

type ProcessEnvAugmented = import("@arkenv/bun-plugin").ProcessEnvAugmented<
  typeof import("./env").Env
>;

declare namespace NodeJS {
  interface ProcessEnv extends ProcessEnvAugmented {}
}
```

Next.js uses `withArkEnv` codegen (`env.gen.ts`) for the same kind of
boundary typing. See
[Client vs. server](/docs/validating-your-environment/client-vs-server).
