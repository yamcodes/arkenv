---
title: Add to an existing repository
description: Using ArkEnv with your existing repository.
---

ArkEnv can be adopted incrementally in a repo that already has application
code. When the interactive CLI finds a `package.json`, it detects your
stack, generates schema files, and wires framework integrations.

<Steps>
  <Step>
    ### Run the interactive CLI

    ```package-install
    npx arkenv@latest init
    ```

    The CLI refuses a dirty git working tree. Commit or stash
    (`git stash -u`) first, or pass `--force` if you accept overwriting
    generated files.

    <Callout type="warn" title="Security">
      The CLI never reads `.env` or `.env.local`. Schema key names come
      from `.env.example` if you have one, otherwise from `process.env`
      / `import.meta.env` usage in source.
    </Callout>
  </Step>

  <Step>
    ### Answer the wizard

    The CLI asks about framework, layout (flat or strict on Next.js /
    Nuxt), validator, and hosting preset. Schema keys come from
    `.env.example` if you have one, otherwise from `process.env` /
    `import.meta.env` usage in source. If `compilerOptions.strict` is
    off in `tsconfig.json`, the wizard can enable it.
  </Step>

  <Step>
    ### Review generated files

    Typical Next.js flat layout:

    <Files>
      <Folder name="my-app" defaultOpen>
        <File name="env.ts" />

        <File name=".env.example" />

        <File name=".env" />

        <Folder name="generated" defaultOpen>
          <File name="env.gen.ts" />
        </Folder>

        <Folder name="app" defaultOpen>
          <File name="page.tsx" />
        </Folder>

        <File name="next.config.ts" />
      </Folder>
    </Files>

    If the project has a `src/` directory, the schema lands at
    `src/env.ts` instead. On Next.js, the CLI wraps `next.config.ts`
    with `withArkEnv`.
  </Step>

  <Step>
    ### Use the validated `env` object

    Copy example values into `.env` so your framework can load them.
    ArkEnv validates; it does not load `.env` files. Then import `env`
    in application code.

    ```bash title="Terminal"
    cp .env.example .env
    ```

    ```ts title="./app/page.tsx" twoslash
    // @filename: env.ts
    import arkenv from "@arkenv/core";

    export const env = arkenv({
      DATABASE_URL: "string",
    });

    // @filename: app/page.tsx
    // ---cut---
    import { env } from "../env";

    console.log(env.DATABASE_URL);
    ```
  </Step>
</Steps>
