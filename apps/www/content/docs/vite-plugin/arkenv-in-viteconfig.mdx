:::note
This is an **advanced setup** for when you need to access environment variables *inside* your `vite.config.ts` (e.g., to set `server.port`). For standard application usage, see the [Introduction](/docs/vite-plugin).
:::

Vite doesn't automatically load `.env*` files when evaluating your `vite.config.ts` - those variables are only available later in your application code via `import { env } from "./env"`. If you need environment variables in your config (like setting `server.port` or conditionally enabling plugins), you'll need to load them manually using Vite's `loadEnv` helper.

:::important
You must have the core `@arkenv/core` package installed as a dependency in your project. See [ArkEnv quickstart](/docs/arkenv/quickstart) for instructions.
:::

Validate config-time values with core `arkenv()` and `loadEnv`. Register `@arkenv/vite-plugin` with no schema — it rewrites `src/env.ts` in the client graph.

```ts title="src/env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv({
	PORT: "number.port",
	VITE_API_URL: "string",
});
```

```ts title="vite.config.ts" twoslash
import arkenvVitePlugin from "@arkenv/vite-plugin";
import arkenv from "@arkenv/core";
import { defineConfig, loadEnv } from "vite";

export default defineConfig(({ mode }) => {
	const env = arkenv(
		{
			PORT: "number.port",
			VITE_API_URL: "string",
		},
		{ env: loadEnv(mode, process.cwd(), "") },
	);

	return {
		plugins: [arkenvVitePlugin()],
		server: {
			port: env.PORT,
		},
	};
});
```

Note how application code and Vite config stay separate:

1. Environment variables needed for the Vite config (`PORT`) are available via `loadEnv()` and validated by core ArkEnv. These server-only variables are not exposed to client code.
2. Public `VITE_*` variables that should be available in your client code (like `VITE_API_URL`) live on `import { env } from "./env"`. The plugin automatically filters that module to only expose variables matching the Vite prefix (defaults to `VITE_`), preventing server-only variables from leaking into the client bundle.
