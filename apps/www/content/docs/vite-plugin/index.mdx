The ArkEnv Vite plugin rewrites your `env.ts` module in the client graph. Define the schema once with `import { env } from "./env"`. On the server graph that module runs boot-time validation; in the client graph, `VITE_*` keys become inlined coerced literals and server-only keys throw if read.

If a variable is missing or fails validation, the plugin will halt the build or dev server immediately with a clear error message. By matching Vite's default security model, only variables prefixed with `VITE_` are exposed to your client bundle.

## Quickstart

The easiest way to get started is with the [ArkEnv CLI](/docs/cli). It automatically configures `@arkenv/vite-plugin` for your existing Vite project, or spins up a new one from a template.

```npm
npx arkenv@latest init
```

<Accordions>
  <Accordion title="Manual Installation">
    ### Installation [step] [!toc]

    ```package-install
    @arkenv/core @arkenv/vite-plugin arktype
    ```

    :::note
    `@arkenv/vite-plugin` lists `@arkenv/core` and `@arkenv/standard` as **optional peer dependencies**. Install one engine so it resolves to a single root-level instance and avoids dual-package hazards.
    :::

    For a Standard Schema setup (e.g., Zod, Valibot) without ArkType:

    ```package-install
    @arkenv/standard @arkenv/vite-plugin zod
    ```

    ### Define `env.ts` [step] [!toc]

    `src/env.ts` (or `env.ts` at the project root) is the typed source of truth:

    ```ts title="src/env.ts" twoslash
    import arkenv from "@arkenv/core";

    export const env = arkenv({
    	PORT: "number.port",
    	VITE_MY_VAR: "string"
    });
    ```

    ### Configure plugin [step] [!toc]

    Register the plugin with no schema argument. It auto-discovers `src/env.ts` or `env.ts`.

    ```ts title="vite.config.ts" twoslash
    import arkenv from "@arkenv/vite-plugin";
    import { defineConfig } from "vite";

    export default defineConfig({
    	plugins: [arkenv()]
    });
    ```

    Pass `schemaPath` or `clientPrefix` if you need to override the defaults:

    ```ts title="vite.config.ts" twoslash
    import arkenv from "@arkenv/vite-plugin";
    import { defineConfig } from "vite";

    export default defineConfig({
    	plugins: [arkenv({ schemaPath: "src/env.ts", clientPrefix: "VITE_" })]
    });
    ```

    ### Logging [step] [!toc]

    Pass `logLevel` or a custom `logger` in the plugin config object:

    ```ts title="vite.config.ts" twoslash
    import arkenv from "@arkenv/vite-plugin";
    import { defineConfig } from "vite";

    export default defineConfig({
    	plugins: [arkenv({ logLevel: "warn" })],
    });
    ```

    ### Use in your code [step] [!toc]

    Import the validated `env` object. Do not read `import.meta.env` for schema keys.

    ```tsx title="src/App.tsx" twoslash
    // @filename: env.ts
    import arkenv from "@arkenv/core";
    export const env = arkenv({
    	PORT: "number.port",
    	VITE_MY_VAR: "string"
    });

    // @filename: App.tsx
    // ---cut---
    import { env } from "./env";

    const apiUrl = env.VITE_MY_VAR;
    //      ^?
    ```
  </Accordion>
</Accordions>

With this setup, if any environment variable is missing or invalid, your dev server won't start and your production build will fail with an error:

```bash title="Terminal"
ArkEnvError: Errors found while validating environment variables
  VITE_MY_VAR must be a string (was missing)
  PORT must be an integer between 0 and 65535 (was "hello")
```

## Using Standard Schema validators (Zod, Valibot, etc.)

This plugin uses ArkType for validation, which natively supports Standard Schema. You can freely mix ArkType DSL strings with Zod or Valibot validators in the same schema - no extra configuration needed.

```ts title="src/env.ts" twoslash
import arkenv from "@arkenv/core";
import { z } from "zod";

export const env = arkenv({
	VITE_API_URL: z.string().url(),
	VITE_API_KEY: z.string().min(1),
	VITE_DEBUG: "boolean"
});
```

```ts title="vite.config.ts" twoslash
import arkenv from "@arkenv/vite-plugin";
import { defineConfig } from "vite";

export default defineConfig({
	plugins: [arkenv()]
});
```

```tsx title="src/App.tsx" twoslash
// @filename: env.ts
import arkenv from "@arkenv/core";
import { z } from "zod";
export const env = arkenv({
	VITE_API_URL: z.string().url(),
	VITE_API_KEY: z.string().min(1),
	VITE_DEBUG: "boolean"
});

// @filename: App.tsx
// ---cut---
import { env } from "./env";

const apiUrl = env.VITE_API_URL;
//      ^?
```

### ArkType-free mode (Standard Mode)

If you want to use Zod, Valibot, or other Standard Schema validators **without** installing `arktype` in your Vite project:

1. Install `@arkenv/standard` and `@arkenv/vite-plugin`:

```package-install
@arkenv/standard @arkenv/vite-plugin zod
```

2. Define `env.ts` with `@arkenv/standard` and register `@arkenv/vite-plugin/standard`:

```ts title="src/env.ts"
import arkenv from "@arkenv/standard";
import { z } from "zod";

export const env = arkenv({
  VITE_API_URL: z.string().url(),
  VITE_API_KEY: z.string().min(1),
});
```

```ts title="vite.config.ts"
import arkenv from "@arkenv/vite-plugin/standard";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [arkenv()]
});
```

For advanced workflows, see [using ArkEnv in Vite config](/docs/vite-plugin/arkenv-in-viteconfig).
