## What is ArkEnv?

ArkEnv is a typesafe environment variable validation library for JavaScript and TypeScript apps. It is designed for fail-fast checks and inferred types, and it works the same way in a single app or a [monorepo that reuses one schema](/docs/validating-environment-variables/reusing-schemas).

Write your schema in [ArkType](https://arktype.io), [Zod](https://zod.dev), [Valibot](https://valibot.dev), or any [Standard Schema](https://standardschema.dev/) validator. ArkEnv validates it, parses the values, and gives you a typed `env` object.

## The `process.env` problem

Environment variables are how apps get configured - but **`process.env` is untyped**. Every key is `string | undefined`. `"false"` is truthy. `PORT` might be `"8080a"`. A single app might have **dozens of ad-hoc checks** that drift from the real contract.

```ts title="./server.ts" twoslash
const host = process.env.HOST;
//    ^?
const port = process.env.PORT;
//    ^?

console.log(`Listening at http://${host}:${port}`);
```

These gaps show up late: a deploy that looked green, a secret that leaked into a client bundle, a boolean that never meant what you thought. Feedback loops need to be fast so you can ship with the configuration you intended.

## The `env` solution

**ArkEnv solves your untyped env problem.** You declare a schema once. Calling `arkenv()` proves the process has that configuration **before application code runs**.

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv({
  HOST: "string.host = 'localhost'",
  PORT: "number.port = 3000",
});
```

```ts title="./server.ts" twoslash
// @filename: env.ts
import arkenv from "@arkenv/core";

export const env = arkenv({
  HOST: "string.host = 'localhost'",
  PORT: "number.port = 3000",
});

// @filename: server.ts
// ---cut---
import { env } from "./env";

const host = env.HOST;
//    ^?
const port = env.PORT;
//    ^?

console.log(`Listening at http://${host}:${port}`);
```

Additionally, fullstack apps have to keep secrets off the client. You may need a public prefix, *then* a runtime guard, *then* a bundler exclude...

ArkEnv **enforces that split** in [Next.js](/docs/guides/frameworks/nextjs), [Nuxt](/docs/guides/frameworks/nuxt), [Vite](/docs/guides/frameworks/vite), and [Bun](/docs/guides/frameworks/bun). Server values stay out of the client graph.

ArkEnv can be **adopted incrementally** and you can **add it to any repository in just a few minutes**. It uses the validator you've already written and a single `env.ts` file. [`@arkenv/core`](/docs/reference/core) accepts ArkType and Standard Schema validators; [`@arkenv/standard`](/docs/reference/standard) is there if you want to skip the `arktype` dependency.
