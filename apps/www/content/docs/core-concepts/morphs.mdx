---
title: Morphs
description: Transform values during validation with ArkType morphs.
---

A morph reshapes a value as part of validation. In `@arkenv/core`, morphs come from [ArkType](https://arktype.io/docs/morphs)'s `.pipe` API via `type()`.

Morphs are for custom transforms. Everyday string-to-number and string-to-boolean conversion is handled by [coercion](/docs/core-concepts/coercion), which runs first on a copy of the input.

## Basic morph

```ts title="./env.ts" twoslash
import arkenv, { type } from "@arkenv/core";

export const env = arkenv({
  BUILD_ID: type("string").pipe((value) => value.trim().toUpperCase()),
  PORT: "number.port = 3000",
});
```

`BUILD_ID` is still validated as a string, then transformed. `PORT` uses coercion, not a manual morph.

## Morph after coercion

Coercion can feed a morph. Here the string `"42"` becomes a number before your pipe runs:

```ts title="./env.ts" twoslash
import arkenv, { type } from "@arkenv/core";

export const env = arkenv(
  {
    RETRY_COUNT: type("number").pipe((n) => Math.max(0, n)),
  },
  { env: { RETRY_COUNT: "3" } },
);

env.RETRY_COUNT; // 3
```

With `{ coerce: false }`, `"3"` never becomes a number unless the morph accepts a string itself.

## When to morph vs coerce

| Need                                          | Prefer                                                    |
| --------------------------------------------- | --------------------------------------------------------- |
| `"3000"` → `number`, `"true"` → `boolean`     | [Coercion](/docs/core-concepts/coercion) (default on)     |
| Trim, normalize, clamp, map enums             | Morph (`.pipe`)                                           |
| Validator-owned transforms (Zod `.transform`) | [`@arkenv/standard`](/docs/core-concepts/standard-schema) |

## Standard Schema

`@arkenv/standard` has no ArkType `type()` morphs. Put transforms on the validator (for example Zod `.transform` / `.pipe`) before the value reaches your app.
