[Standard Schema](https://standardschema.dev/) is a shared interface for TypeScript validators. `@arkenv/standard` speaks that interface so you can keep Zod or Valibot without installing ArkType.

For coercion, ArkEnv introspects each validator's **JSON Schema** metadata (when the library exposes Standard JSON Schema v1) to decide which string paths need conversion before validation runs.

## JSON Schema interop

ArkEnv's pre-coercion step needs to know target types. For Standard Schema validators it reads JSON Schema through the library's metadata hooks:

| Library                                        | JSON Schema support             |
| ---------------------------------------------- | ------------------------------- |
| Zod (v4.2+)                                    | Yes                             |
| Valibot (v1.2+ with `@valibot/to-json-schema`) | Yes                             |
| Zod Mini                                       | Yes                             |
| VineJS (v4.3+)                                 | Yes                             |
| Other Standard JSON Schema v1 validators       | Yes, when metadata is available |

When metadata is missing, rely on the validator's own coercion (`z.coerce.number()`) or disable ArkEnv coercion and validate raw strings. See [Coercion](/docs/core-concepts/coercion).

## Two engines

|                | `@arkenv/core`               | `@arkenv/standard`                     |
| -------------- | ---------------------------- | -------------------------------------- |
| DSL            | ArkType strings + `type()`   | Per-key Standard Schema validators     |
| Keywords       | `string.host`, `number.port` | None                                   |
| Peer `arktype` | Required                     | None                                   |
| Coercion       | Built-in                     | When the validator exposes JSON Schema |
| Plugins        | `@arkenv/*/…`                | Matching `/standard` subpaths          |

Prefer `@arkenv/core` for new TypeScript apps that can take ArkType. Reach for `@arkenv/standard` when you are migrating an existing Zod/Valibot schema or must stay ArkType-free.

## Usage

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/standard";
import { z } from "zod";

export const env = arkenv({
  DATABASE_URL: z.string().url(),
  PORT: z.coerce.number().int().min(0).max(65535).default(3000),
  NODE_ENV: z.enum(["development", "production", "test"]).default("development"),
});
```

Runtime [options](/docs/reference/options) match core: `env`, `coerce`, `safe`, `arrayFormat`, and the rest.

## Packaging

Engines are separate packages so peer dependencies stay honest. Framework plugins stay single packages with `/standard` subpaths (`@arkenv/nextjs/standard`, `@arkenv/vite-plugin/standard`, and so on) instead of a second npm package per host.

## Coercion note

ArkEnv still pre-coerces when it can read JSON Schema from the validator. Libraries without that metadata need their own coerce helpers (for example `z.coerce.number()`). See [Coercion](/docs/core-concepts/coercion).
