ArkEnv pairs runtime validation with TypeScript inference. The schema is the single source of truth for both.

## Canonical surface: `env`

Import a validated object. Do not sprinkle `process.env` reads through the app.

```ts title="./env.ts" twoslash
import arkenv, { type Infer } from "@arkenv/core";

const schema = {
  DATABASE_URL: "string",
  PORT: "number.port = 3000",
} as const;

export const env = arkenv(schema);
export type Env = Infer<typeof schema>;

env.PORT; // number
```

This object surface is the product default across Next.js, Nuxt, Vite, and Bun. Plugins and codegen exist to deliver that object safely on each host, not to invent a second dialect.

## Inference paths

| Input                                  | Result                                   |
| -------------------------------------- | ---------------------------------------- |
| Declarative map (`{ PORT: "number" }`) | `Infer<typeof schema>`                   |
| Compiled `type({ ... })`               | `typeof Env.infer` / `Infer<typeof Env>` |
| Standard Schema field map              | Output types from each validator         |

Hovering `env` in the editor shows the coerced output types when coercion is enabled.

## Framework typing

- **Next.js:** generated `env.gen.ts` factory plus full schema inference; a Proxy enforces server/client access at runtime
- **Nuxt:** same object model with module wiring
- **Vite / Bun:** transform mode rewrites the client copy of `env.ts` so public keys stay typed and coerced; optional ambient helpers (`ImportMetaEnvAugmented`, `ProcessEnvAugmented`) support SPA-only accessor mode

Flat layouts may expose server **key names** to client TypeScript while blocking values. Strict layouts keep server modules out of the client graph. See [Client vs. server](/docs/validating-environment-variables/client-vs-server).

## What typesafety is not

Types do not load `.env` files. Types do not stop you from reading `process.env` with a cast. ArkEnv's guarantee holds when application code imports `env` and validation runs at boot or build.
