---
title: Typesafety
description: Infer strict TypeScript types directly from your environment schema.
---

The schema is the single source of truth for runtime checks and
TypeScript types. That holds for ArkType via `@arkenv/core` and for
Zod or Valibot via `@arkenv/standard`.

## Canonical surface: `env`

Import a validated object. Do not sprinkle `process.env` reads through
the app.

<Tabs items={["ArkType (@arkenv/core)", "Zod (@arkenv/standard)"]}>
  <Tab value="ArkType (@arkenv/core)">
    ```ts title="./env.ts" twoslash
    import arkenv, { type Infer } from "@arkenv/core";

    const schema = {
    	DATABASE_URL: "string",
    	PORT: "number.port = 3000",
    } as const;

    export const env = arkenv(schema);
    export type Env = Infer<typeof schema>;

    env.PORT; // number
    ```
  </Tab>

  <Tab value="Zod (@arkenv/standard)">
    ```ts title="./env.ts" twoslash
    import arkenv from "@arkenv/standard";
    import { z } from "zod";

    const schema = {
    	DATABASE_URL: z.string().url(),
    	PORT: z.number().int().min(0).max(65535).default(3000),
    };

    export const env = arkenv(schema);
    export type Env = typeof env;

    env.PORT; // number
    ```
  </Tab>
</Tabs>

This object is the default across Next.js, Nuxt, Vite, and Bun. Plugins
and codegen deliver it on each host. Use `/standard` subpaths when the
schema is Standard Schema.

## Inference paths

| Input | Result |
| ----- | ------ |
| ArkType declarative map (`{ PORT: "number" }`) | `Infer<typeof schema>` from `@arkenv/core` |
| Compiled `type({ ... })` | `typeof Env.infer` / `Infer<typeof Env>` |
| Standard Schema field map (Zod, Valibot, …) | `typeof env` after `arkenv(schema)`, or each validator's own infer helper |

Hovering `env` in the editor shows the coerced output types when
coercion is enabled.

## Framework typing

- **Next.js:** generated `env.gen.ts` factory plus full schema
  inference; a Proxy enforces server/client access at runtime
- **Nuxt:** same object model with module wiring
- **Vite / Bun:** transform mode rewrites the client copy of `env.ts`
  so public keys stay typed and coerced; import `{ env }` from that
  module instead of native accessors for schema keys

Flat layouts may expose server **key names** to client TypeScript while
blocking values. Strict layouts keep server modules out of the client
graph. See
[Client vs. server](/docs/validating-your-environment/client-vs-server).

## Where the guarantee holds

Typesafety holds when application code imports `env` and validation
runs at boot or build. Casting `process.env`, or skipping the import,
bypasses it. Types do not load `.env` files.
