ArkType strings can describe a port or a host without wrapping each
key. ArkEnv's core engine takes those DSL strings, adds `number.port`
and `string.host`, and coerces strings before validation.

`arktype` is a required peer of `@arkenv/core`. How this engine differs
from Zod and Valibot is in [Validators](/docs/validators).

## Installation

Install `@arkenv/core` and its peer `arktype`. The peer is required.
`@arkenv/core` itself has no runtime dependencies.

```package-install
npm install @arkenv/core arktype
```

## Define your schema

Put the schema in `env.ts` and import `{ env }` where the process
starts. A missing key or a value that fails the schema throws
[`ArkEnvError`](/docs/reference/core) at that import, before the rest of
the app runs. DSL strings cover the common keys. Reach for compiled
`type()` when you need a morph or a function default.

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv({
  DATABASE_URL: "string",
  PORT: "number.port = 3000",
  DEBUG: "boolean = false",
  NODE_ENV: "'development' | 'production' | 'test' = 'development'",
});
```

## Automatic coercion

Environment variables arrive as strings. ArkEnv reads the compiled
ArkType schema's JSON Schema and coerces those strings into numbers,
booleans, and arrays before validation, so `PORT` is a `number` in
application code.

```ts title="./env.ts" twoslash
import arkenv from "@arkenv/core";

export const env = arkenv(
  {
    PORT: "number.port",
    DEBUG: "boolean",
    TAGS: "string[]",
  },
  {
    env: {
      PORT: "8080",
      DEBUG: "true",
      TAGS: "web, api",
    },
  },
);

env.PORT; // number
env.DEBUG; // boolean
env.TAGS; // string[]
```

To disable automatic string conversion and preserve raw strings for custom morphs,
pass `{ coerce: false }`. Learn more in [Coercion](/docs/core-concepts/coercion-and-parsing).

## Defaults and optionals

ArkType syntax supports inline default values and optional properties:

| Pattern                            | Behavior                                                         |
| :--------------------------------- | :--------------------------------------------------------------- |
| `= 'value'` / `= 3000`             | Fallback value when the variable is undefined                    |
| `string \| undefined` or `string?` | Optional environment variable                                    |
| `emptyAsUndefined: true`           | Converts empty strings (`""`) to `undefined` so defaults trigger |

For specialized validators like `string.host` and `number.port`, see
[Keywords](/docs/reference/keywords). To build complex custom schemas or morphs,
see [Defining types](/docs/core-concepts/defining-your-schema).
