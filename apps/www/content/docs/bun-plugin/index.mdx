:::note
For standard backend applications running on Bun, you likely don't need this plugin. Instead, use the agnostic [core arkenv package](/docs/arkenv) directly. This plugin is specifically designed to handle client-side environment variable inlining when using Bun as a bundler and fullstack server.
:::

The ArkEnv Bun plugin rewrites your `env.ts` module in browser bundles. Define your schema with `import { env } from "./env"`. On the server graph that module runs boot-time validation; in browser bundles, `BUN_PUBLIC_*` keys become inlined coerced literals and server-only keys throw if read.

If a variable is missing or invalid, it immediately halts execution with a detailed validation error. By matching Bun's default security model, only variables prefixed with `BUN_PUBLIC_` are exposed to client-side code.

## Quickstart

The easiest way to get started is with the [ArkEnv CLI](/docs/cli). It automatically configures `@arkenv/bun-plugin` for your existing Bun project, or spins up a new one from a template.

```npm
npx arkenv@latest init
```

<Accordions>
  <Accordion title="Manual Installation">
    ### Installation [step] [!toc]

    ```package-install
    @arkenv/core @arkenv/bun-plugin arktype
    ```

    :::note
    `@arkenv/bun-plugin` lists `@arkenv/core` and `@arkenv/standard` as **optional peer dependencies**. Install one engine so it resolves to a single root-level instance and avoids dual-package hazards.
    :::

    For a Standard Schema setup (e.g., Zod, Valibot) without ArkType:

    ```package-install
    @arkenv/standard @arkenv/bun-plugin zod
    ```

    ### Define `env.ts` [step] [!toc]

    `src/env.ts` (or `env.ts` at the project root) is the typed source of truth:

    ```ts title="src/env.ts" twoslash
    import arkenv from "@arkenv/core";

    export const env = arkenv({
      BUN_PUBLIC_API_URL: "string",
      BUN_PUBLIC_DEBUG: "boolean",
    });
    ```

    ### Configure plugin [step] [!toc]

    The plugin auto-discovers `src/env.ts` or `env.ts`. This requires configuration in **both** `bunfig.toml` (for `Bun.serve`) and your build script (for `Bun.build`).

    #### Configure for Bun.serve (dev mode)

    ```toml title="bunfig.toml"
    [serve.static]
    plugins = ["@arkenv/bun-plugin"]
    ```

    #### Configure for Bun.build (build mode)

    Register the plugin with no schema argument:

    ```ts title="build.ts"
    import arkenv from "@arkenv/bun-plugin";

    await Bun.build({
      entrypoints: ["./app.tsx"],
      outdir: "./dist",
      plugins: [arkenv()],
    });
    ```

    ### Use in your code [step] [!toc]

    Import the validated `env` object. Do not read `process.env` for schema keys.

    ```tsx title="src/App.tsx" twoslash
    // @filename: env.ts
    import arkenv from "@arkenv/core";
    export const env = arkenv({
      BUN_PUBLIC_API_URL: "string",
      BUN_PUBLIC_DEBUG: "boolean",
    });

    // @filename: App.tsx
    // ---cut---
    import { env } from "./env";

    const apiUrl = env.BUN_PUBLIC_API_URL;
    //      ^?
    ```
  </Accordion>
</Accordions>

## Custom schema location

If your schema is at a custom path, pass `schemaPath` to the plugin:

### For Bun.build

```ts title="build.ts"
import arkenv from "@arkenv/bun-plugin";

await Bun.build({
  entrypoints: ["./app.tsx"],
  outdir: "./dist",
  plugins: [arkenv({ schemaPath: "custom/env.ts", clientPrefix: "BUN_PUBLIC_" })],
});
```

### For Bun.serve

Create a plugin wrapper file and reference it in `bunfig.toml`:

```ts title="plugins/arkenv.ts"
import arkenv from "@arkenv/bun-plugin";

export default arkenv({
  schemaPath: "custom/env.ts",
  clientPrefix: "BUN_PUBLIC_",
});
```

```toml title="bunfig.toml"
[serve.static]
plugins = ["./plugins/arkenv.ts"]
```

## Using Standard Schema validators (Zod, Valibot, etc.)

This plugin uses ArkType for validation, which natively supports Standard Schema. You can freely mix ArkType DSL strings with Zod or Valibot validators in the same schema - no extra configuration needed.

```ts title="src/env.ts" twoslash
import arkenv from "@arkenv/core";
import { z } from "zod";

export const env = arkenv({
  BUN_PUBLIC_API_URL: z.string().url(),
  BUN_PUBLIC_DEBUG: "boolean",
});
```

```tsx title="src/App.tsx" twoslash
// @filename: env.ts
import arkenv from "@arkenv/core";
import { z } from "zod";
export const env = arkenv({
  BUN_PUBLIC_API_URL: z.string().url(),
  BUN_PUBLIC_DEBUG: "boolean",
});

// @filename: App.tsx
// ---cut---
import { env } from "./env";

const apiUrl = env.BUN_PUBLIC_API_URL;
//      ^?
```

### ArkType-free mode (Standard Mode)

If you want to use Zod, Valibot, or other Standard Schema validators **without** installing `arktype` in your Bun project:

1. Install `@arkenv/standard` and `@arkenv/bun-plugin`:

```package-install
@arkenv/standard @arkenv/bun-plugin zod
```

2. Define `env.ts` with `@arkenv/standard`:

```ts title="src/env.ts"
import arkenv from "@arkenv/standard";
import { z } from "zod";

export const env = arkenv({
  BUN_PUBLIC_API_URL: z.string().url(),
  BUN_PUBLIC_DEBUG: z.boolean(),
});
```

3. Register `@arkenv/bun-plugin/standard` in your build script:

```ts title="build.ts"
import arkenv from "@arkenv/bun-plugin/standard";

await Bun.build({
  entrypoints: ["./app.tsx"],
  outdir: "./dist",
  plugins: [arkenv()],
});
```

4. To use the static dev server plugin with auto-discovery, update `bunfig.toml` to reference `@arkenv/bun-plugin/standard`:

```toml title="bunfig.toml"
[serve.static]
plugins = ["@arkenv/bun-plugin/standard"]
```

## Logging

Pass `logLevel` or a custom `logger` in the plugin config object:

```ts title="build.ts"
import arkenv from "@arkenv/bun-plugin";

await Bun.build({
  entrypoints: ["./app.tsx"],
  outdir: "./dist",
  plugins: [arkenv({ logLevel: "warn" })],
});
```

You can also set `ARKENV_LOG_LEVEL` globally when no custom logger is provided.
